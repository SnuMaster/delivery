# 택배허브

운송장번호를 한 화면에 모아 두고 각 택배사의 **공식 배송조회**로 연결하는 개인용 웹앱입니다. 배송 상태나 도착 예정일을 만들어 내거나, 숫자만 보고 택배사를 단정하지 않습니다.

배포 주소: `https://snumaster.github.io/delivery/`

## 지금 되는 것

- CJ대한통운, 한진, 롯데, 로젠, 우체국, EMS, 경동, 대신택배의 공식 조회 연결
- 운송장·택배사·메모·받음 표시 관리
- 문자/메일을 붙여 넣어 운송장 후보만 보수적으로 추출
- iPhone: 기존 문자는 복사·붙여넣기, 앞으로의 배송 문자는 iPhone 단축어로 운송장 후보만 자동 등록(베타)
- JSON 백업과 안전한 병합 가져오기
- 이메일 아이디 + 비밀번호 회원가입/로그인, 비밀번호 재설정
- 로그인 후 Supabase RLS로 분리된 기기 간 택배 목록 동기화
- 기기 간 삭제가 되살아나지 않도록 최소한의 삭제 기록도 동기화

회원가입의 “아이디”는 이메일입니다. 비밀번호는 Supabase Auth가 처리하며, 이 저장소·GitHub Pages·브라우저 코드에는 비밀번호나 서버 관리자 키가 들어 있지 않습니다.

## 메일 연동의 실제 범위

### 가장 쉬운 방법: 복사·붙여넣기

배송 문자나 주문 메일을 열어 내용을 전체 복사한 뒤 택배허브에 붙여넣으면, 운송장 후보만 보수적으로 찾습니다. 이 방법은 로그인이나 메일 비밀번호 없이 바로 쓸 수 있습니다. 후보에는 배송과 무관한 숫자가 섞일 수 있으므로, 번호와 택배사를 확인한 뒤 추가합니다.

### Gmail

Gmail 자동 찾기는 사이트에서 바로 사용할 수 있습니다. 택배허브 로그인과 별개로 사용자가 **Gmail 연결하고 운송장 찾기**를 눌렀을 때만 Google 동의 화면을 열고, 최근 180일 배송·주문 메일 **최대 50개**에서 운송장 후보만 찾습니다. 메일 원문·첨부파일·단기 액세스 토큰은 브라우저 밖으로 보내거나 장기 저장하지 않습니다. 한 메일을 읽지 못해도 나머지 결과는 계속 보여 줍니다.

현재 Google OAuth는 개인 테스트 모드입니다. 등록된 테스트 Google 계정은 바로 연결할 수 있고, 다른 사람이 쓰게 하려면 Google Cloud에 그 계정을 테스트 사용자로 추가하거나 Google의 앱 게시·검증 절차를 완료해야 합니다.

### 네이버 메일

개인 `@naver.com` 메일은 Gmail처럼 “메일 읽기” 권한만 허용해 받은편지함을 검색하는 공식 OAuth API를 제공하지 않습니다. 네이버가 외부 프로그램 연결에 요구하는 방식은 IMAP/POP와 앱 비밀번호이므로, 이 정적 웹사이트는 네이버 비밀번호나 앱 비밀번호를 받거나 저장하지 않습니다.

따라서 네이버 메일은 **메일 열기 → 배송 메일 전체 복사 → 택배허브에 붙여넣기**로 사용합니다. 개인 메일 비밀번호를 받는 서버 연동을 자동 연동처럼 표시하지 않습니다. NAVER WORKS 메일은 별도의 기업용 Mail API가 있으나, 일반 개인 네이버 메일과는 다른 서비스입니다.

### iPhone 문자

웹사이트나 일반 iOS 앱은 iPhone의 전체 SMS/iMessage 기록이나 과거 문자를 자동으로 읽을 수 없습니다. 다만 iPhone **단축어의 메시지 자동화**를 쓰면, 앞으로 새로 들어오는 조건 일치 메시지에서 iPhone이 운송장 후보만 추출해 택배허브에 자동 등록할 수 있습니다.

1. 택배허브에서 **문자·메일 → iPhone 자동 등록 연결**을 열고 로그인합니다.
2. 연결 키를 만들고, 화면에 표시되는 주소와 키를 iPhone 단축어 설정에 한 번만 붙여넣습니다.
3. iPhone 단축어 → 자동화 → 메시지에서 `운송장` 같은 배송 조건을 정하고 **즉시 실행**으로 설정합니다.
4. 단축어에서 문자 원문 대신 정규식 일치 결과(운송장 후보)만 JSON POST로 보냅니다. 사이트 화면에 같은 설정 순서가 표시됩니다.

연결 키는 계정 비밀번호와 분리된 iPhone 전용 코드입니다. DB에는 키의 해시와 마지막 여섯 글자만 보관하며, 키·문자 원문·발신자·전화번호는 저장하지 않습니다. 키를 잃어버리거나 iPhone을 분실하면 **연결 코드 바꾸기** 또는 **연결 해제**를 누르면 기존 키가 즉시 무효화됩니다. 같은 후보를 반복 전송해도 중복 방지 지문과 운송장 고유키로 한 번만 처리합니다. 자동 등록된 번호도 택배사가 미지정된 상태로 저장되므로, 공식 조회 전에 사용자가 택배사를 확인해야 합니다.

## 정확성 원칙

- 휴대폰 번호만으로 모든 택배사를 통합 조회하는 공개 API는 없습니다.
- 국내 숫자 운송장 형식은 택배사끼리 겹칩니다. 숫자 길이·앞자리만으로 CJ/한진 등을 확정하지 않습니다.
- `AA123456789BB` S10 국제우편 코드는 EMS 후보로만 안내하고 사용자가 확인합니다.
- 실제 배송 상태와 이력은 항상 해당 택배사의 공식 조회 페이지에서 확인합니다.

## 개인정보·보안

- 공개 브라우저 설정에는 Supabase **publishable key**만 둡니다. `service_role` 키, OAuth client secret, Gmail/NAVER 비밀번호·앱 비밀번호는 절대 넣지 않습니다.
- 모든 공개 테이블은 RLS가 켜져 있으며, 로그인한 사용자는 자기 `user_id`의 데이터만 읽고 쓸 수 있습니다.
- 삭제한 운송장은 번호와 시간만 담은 사용자 전용 삭제 기록으로 남겨, 오프라인 기기가 나중에 같은 번호를 되살리지 못하게 합니다.
- 메일 연동 테이블은 상태/중복 방지용 지문만 저장하도록 설계했습니다. 메일·문자 원문, 첨부파일, 제공자 메시지 ID, 토큰, 앱 비밀번호는 저장하지 않습니다.
- Content Security Policy를 적용해 허용한 Supabase/Google 연결 외의 스크립트·데이터 연결을 제한합니다.

## 소유자가 처음 한 번 할 설정

### 1. Supabase Auth 리디렉션

Supabase Dashboard → **Authentication → URL Configuration**에서 아래처럼 설정합니다.

- Site URL: `https://snumaster.github.io/delivery/`
- Redirect URLs: `https://snumaster.github.io/delivery/`

이 설정이 있어야 이메일 인증과 비밀번호 재설정 링크가 사이트로 돌아옵니다. 테스트용 기본 이메일 발송은 제한이 있으므로, 실제 여러 사용자가 쓰는 서비스로 바꾸기 전에는 Custom SMTP도 설정하세요.

### 2. Gmail 자동 찾기 설정 (이미 이 배포에는 완료됨)

1. Google Cloud에서 Gmail API를 활성화합니다.
2. OAuth 동의 화면을 만들고, 웹용 OAuth Client ID를 생성합니다.
3. Authorized JavaScript origins에 `https://snumaster.github.io`를 넣습니다.
4. 테스트 중이면 본인 Google 계정을 테스트 사용자에 추가합니다.
5. 생성된 **Client ID만** `supabase-config.js`의 `GMAIL_CONFIG.clientId`에 넣고 배포합니다. Client secret은 넣지 않습니다.

이 저장소의 Google Cloud 프로젝트에는 위 설정이 적용되어 있습니다. Gmail 연동은 사용자가 누를 때마다 동의를 받고 단기 토큰으로만 작동합니다. 자동 백그라운드 스캔·원문 보관은 이 버전에 포함하지 않습니다.

### 계정 전환 시 브라우저 목록

로그인 직전 이 브라우저에 저장돼 있던 목록이 있으면, 해당 목록을 새 계정에 가져올지 아니면 이 기기에서 지울지를 먼저 선택합니다. 로그아웃할 때는 동기화가 끝난 뒤 이 기기의 목록을 지워 다른 사람이 같은 브라우저에서 이전 목록을 보거나 자기 계정으로 가져가지 못하게 합니다.

## 개발·검증

```bash
npm test
node --check app.js
node --check cloud.js
node --check gmail.js
node --check supabase/functions/iphone-shortcut-ingest/iphone-shortcut.js
node --check supabase/functions/iphone-shortcut-ingest/index.js
node --check supabase/functions/iphone-shortcut-setup/index.js
```

테스트는 번호 정규화, 보수적 택배사 감지, 휴대폰 번호 제외, 일괄 추출, 공식 링크, 백업 병합, 클라우드 행 매핑·삭제 기록·동기화 충돌 우선순위를 확인합니다.

## GitHub Pages 배포

`main`에 반영되면 GitHub Actions가 테스트를 통과한 정적 파일을 GitHub Pages에 배포합니다.

처음 한 번만 저장소에서 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택하면 됩니다. 이미 선택했다면 새 커밋 후 워크플로가 자동 실행됩니다.
