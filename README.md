# 택배허브

운송장번호를 한 화면에 모아 두고 각 택배사의 **공식 배송조회**로 연결하는 개인용 웹앱입니다. 배송 상태나 도착 예정일을 만들어 내거나, 숫자만 보고 택배사를 단정하지 않습니다.

배포 주소: `https://snumaster.github.io/delivery/`

## 지금 되는 것

- CJ대한통운, 한진, 롯데, 로젠, 우체국, EMS, 경동, 대신택배의 공식 조회 연결
- 운송장·택배사·메모·받음 표시 관리
- 문자/메일을 붙여 넣어 운송장 후보만 보수적으로 추출
- 아이폰: 배송 문자를 길게 눌러 복사 → **문자·메일** → 붙여넣기
- JSON 백업과 안전한 병합 가져오기
- 이메일 아이디 + 비밀번호 회원가입/로그인, 비밀번호 재설정
- 로그인 후 Supabase RLS로 분리된 기기 간 택배 목록 동기화
- 기기 간 삭제가 되살아나지 않도록 최소한의 삭제 기록도 동기화

회원가입의 “아이디”는 이메일입니다. 비밀번호는 Supabase Auth가 처리하며, 이 저장소·GitHub Pages·브라우저 코드에는 비밀번호나 서버 관리자 키가 들어 있지 않습니다.

## 메일 연동의 실제 범위

### Gmail

Gmail은 사용자가 버튼을 눌렀을 때만 Google 동의 화면을 열고, 최근 90일 중 조건과 맞는 메일 **최대 25개**에서 운송장 후보만 찾도록 설계했습니다. 메일 원문과 단기 액세스 토큰은 브라우저 밖으로 보내거나 장기 저장하지 않습니다.

다만 Gmail 본문 읽기에는 `gmail.readonly` 권한과 이 사이트용 Google OAuth Client ID가 필요합니다. 현재 `supabase-config.js`의 `GMAIL_CONFIG.clientId`는 의도적으로 비어 있으므로, 아래 1회 설정을 마쳐야 버튼이 실제로 Gmail을 읽습니다. 공개 서비스로 많은 사용자가 쓰게 할 때는 Google의 restricted-scope 검증 요건도 검토해야 합니다.

### 네이버 메일

네이버 로그인은 메일함 읽기 권한을 주지 않습니다. IMAP으로 읽으려면 사용자가 네이버에서 IMAP을 켜고 **앱 비밀번호**를 만들어야 하며, 일반 네이버 비밀번호는 절대 받거나 저장하면 안 됩니다.

정적 GitHub Pages에는 IMAP TCP 연결 기능이 없으므로, 현재 버전은 복사·붙여넣기 가져오기를 제공합니다. 네이버 자동 동기화는 별도 전용 메일 수신/IMAP 서비스와 사용자 동의·연결 해제 기능을 갖춘 다음 단계로 분리했습니다. 지원하지 않는 기능을 이미 되는 것처럼 표시하지 않습니다.

### iPhone 문자

웹사이트나 일반 iOS 앱은 iPhone의 전체 SMS/iMessage 기록을 자동으로 읽을 수 없습니다. 그래서 “문자 자동 연동”이라고 약속하지 않고, 복사/붙여넣기 경로를 바로 사용할 수 있게 했습니다. 원하면 이후에 사용자가 직접 실행하는 iOS 단축어를 추가할 수 있습니다.

## 정확성 원칙

- 휴대폰 번호만으로 모든 택배사를 통합 조회하는 공개 API는 없습니다.
- 국내 숫자 운송장 형식은 택배사끼리 겹칩니다. 숫자 길이·앞자리만으로 CJ/한진 등을 확정하지 않습니다.
- `AA123456789BB` S10 국제우편 코드는 EMS 후보로만 안내하고 사용자가 확인합니다.
- 실제 배송 상태와 이력은 항상 해당 택배사의 공식 조회 페이지에서 확인합니다.

## 개인정보·보안

- 공개 브라우저 설정에는 Supabase **publishable key**만 둡니다. `service_role` 키, OAuth client secret, Gmail/NAVER 비밀번호·앱 비밀번호는 절대 넣지 않습니다.
- 모든 공개 테이블은 RLS가 켜져 있으며, 로그인한 사용자는 자기 `user_id`의 데이터만 읽고 쓸 수 있습니다.
- 삭제한 운송장은 번호와 시간만 담은 사용자 전용 삭제 기록으로 남겨, 오프라인 기기가 나중에 같은 번호를 되살리지 못하게 합니다.
- 메일 연동 테이블은 상태/중복 방지용 지문만 저장하도록 설계했습니다. 메일·문자 원문, 첨부파일, 제공자 메시지 ID, 토큰, 앱 비밀번호는 저장하지 않습니다.
- Content Security Policy를 적용해 허용한 Supabase/Google 연결 외의 스크립트·데이터 연결을 제한합니다.

## 소유자가 처음 한 번 할 설정

### 1. Supabase Auth 리디렉션

Supabase Dashboard → **Authentication → URL Configuration**에서 아래처럼 설정합니다.

- Site URL: `https://snumaster.github.io/delivery/`
- Redirect URLs: `https://snumaster.github.io/delivery/`

이 설정이 있어야 이메일 인증과 비밀번호 재설정 링크가 사이트로 돌아옵니다. 테스트용 기본 이메일 발송은 제한이 있으므로, 실제 여러 사용자가 쓰는 서비스로 바꾸기 전에는 Custom SMTP도 설정하세요.

### 2. Gmail 수동 스캔 활성화

1. Google Cloud에서 Gmail API를 활성화합니다.
2. OAuth 동의 화면을 만들고, 웹용 OAuth Client ID를 생성합니다.
3. Authorized JavaScript origins에 `https://snumaster.github.io`를 넣습니다.
4. 테스트 중이면 본인 Google 계정을 테스트 사용자에 추가합니다.
5. 생성된 **Client ID만** `supabase-config.js`의 `GMAIL_CONFIG.clientId`에 넣고 배포합니다. Client secret은 넣지 않습니다.

Gmail 연동은 사용자가 누를 때마다 동의를 받고 단기 토큰으로만 작동합니다. 자동 백그라운드 스캔·원문 보관은 이 버전에 포함하지 않습니다.

### 계정 전환 시 브라우저 목록

로그인 직전 이 브라우저에 저장돼 있던 목록이 있으면, 해당 목록을 새 계정에 가져올지 아니면 이 기기에서 지울지를 먼저 선택합니다. 로그아웃할 때는 동기화가 끝난 뒤 이 기기의 목록을 지워 다른 사람이 같은 브라우저에서 이전 목록을 보거나 자기 계정으로 가져가지 못하게 합니다.

## 개발·검증

```bash
npm test
node --check app.js
node --check cloud.js
node --check gmail.js
```

테스트는 번호 정규화, 보수적 택배사 감지, 휴대폰 번호 제외, 일괄 추출, 공식 링크, 백업 병합, 클라우드 행 매핑·삭제 기록·동기화 충돌 우선순위를 확인합니다.

## GitHub Pages 배포

`main`에 반영되면 GitHub Actions가 테스트를 통과한 정적 파일을 GitHub Pages에 배포합니다.

처음 한 번만 저장소에서 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택하면 됩니다. 이미 선택했다면 새 커밋 후 워크플로가 자동 실행됩니다.
